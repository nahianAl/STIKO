# Undo / Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cmd/Ctrl+Z undoes, and Shift+Cmd/Ctrl+Z / Ctrl+Y redoes, the user's last action on the open file: markup, measurements, cross-section planes, and the 3D model's saved placement.

**Architecture:** One command history per open file (`lib/undo/history.ts`, pure), owned by the portal page and shared through a React context. Array/object state (markup objects, measurements, plane flags) records one step per "quiet moment" through `useCheckpointedState`; plane drags and model placement record explicit steps. One window keydown listener drives undo/redo.

**Tech Stack:** Next.js 14 App Router, React 18, Konva 10 / react-konva, three.js + @react-three/fiber 8 + drei 9, Node 22 `node --test` with native type stripping.

**Spec:** `docs/superpowers/specs/2026-11-20-undo-redo-design.md`

## Global Constraints

- Keyboard only. No on-screen undo/redo buttons.
- Undo: `⌘Z` / `Ctrl+Z`. Redo: `⇧⌘Z` / `Ctrl+Shift+Z` / `Ctrl+Y`.
- Shortcut ignored when focus is in `input`/`textarea`/`select`/`contenteditable`, when `[aria-modal="true"]` exists in the document, while a pointer is held, and while a server step is in flight.
- One timeline per file; `clear()` on every selected-file change. Capacity 200.
- Calibration and display unit are NOT undoable.
- Undo/redo of the model placement re-saves through `PATCH /api/files/[id]/transform`.
- Failure toast copy: `Couldn't undo — the model position wasn't saved.` / `Couldn't redo — the model position wasn't saved.`
- Tested `lib/` modules use RELATIVE imports with the `.ts` extension, never `@/` (node --test cannot resolve the alias). Components may use `@/`.
- Never `git add -A` / `git add .` — three untracked handoff dirs live in the repo root. Add files by name.
- Work on branch `feature/undo-redo` (already created; spec committed as d1b5cee).
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

// lib/undo/history.ts
// The undo/redo timeline for one open file. Plain data — no React, no three, no `@/` imports —
// so the node --test suite can import it directly.
//
// A step carries its own undo and redo because Stiko's state lives in three different places:
// React state (markup, measurements, plane flags), the three.js scene (plane poses) and the
// server (the model's placement). A snapshot of "the state" does not exist to take.

export type UndoDomain = 'markup' | 'measure' | 'section' | 'model';

export interface UndoStep {
  domain: UndoDomain;
  undo: () => void | Promise<void>;
  redo: () => void | Promise<void>;
}

export type UndoOutcome =
  | { status: 'done'; step: UndoStep }
  | { status: 'empty' }
  | { status: 'busy' }
  | { status: 'failed'; step: UndoStep; error: unknown };

export const UNDO_CAPACITY = 200;

export interface UndoHistory {
  /** Push a step. Clears the redo stack: a new action forks the timeline. */
  record(step: UndoStep): void;
  undo(): Promise<UndoOutcome>;
  redo(): Promise<UndoOutcome>;
  /**
   * Remove every step of one domain from both stacks, keeping the rest in order. Safe because
   * the domains never share state: each domain's steps chain only among themselves.
   */
  dropDomain(domain: UndoDomain): void;
  clear(): void;
  /**
   * Register a function run before every undo/redo, so a change that has not been checkpointed
   * yet becomes a step first — otherwise the first undo would skip it. Returns the unregister.
   */
  registerFlush(flush: () => void): () => void;
  /** True while an async step (a server save) is running. */
  isBusy(): boolean;
  depth(): { undo: number; redo: number };
}

export function createUndoHistory(capacity: number = UNDO_CAPACITY): UndoHistory {
  let undoStack: UndoStep[] = [];
  let redoStack: UndoStep[] = [];
  let busy = false;
  const flushes = new Set<() => void>();

  const trim = () => {
    if (undoStack.length > capacity) undoStack.splice(0, undoStack.length - capacity);
  };

  const run = async (direction: 'undo' | 'redo'): Promise<UndoOutcome> => {
    if (busy) return { status: 'busy' };
    for (const flush of [...flushes]) flush();
    const source = direction === 'undo' ? undoStack : redoStack;
    const step = source[source.length - 1];
    if (!step) return { status: 'empty' };
    busy = true;
    try {
      await (direction === 'undo' ? step.undo() : step.redo());
    } catch (error) {
      // Left where it was: the user can try again, and the stacks still describe the state.
      return { status: 'failed', step, error };
    } finally {
      busy = false;
    }
    // Located again by identity rather than popped: the stacks may have been reassigned while
    // an async step was in flight (a file switch clears them). A step that is gone was dropped
    // on purpose and must not come back on the other stack.
    if (direction === 'undo') {
      const i = undoStack.lastIndexOf(step);
      if (i !== -1) { undoStack.splice(i, 1); redoStack.push(step); }
    } else {
      const i = redoStack.lastIndexOf(step);
      if (i !== -1) { redoStack.splice(i, 1); undoStack.push(step); trim(); }
    }
    return { status: 'done', step };
  };

  return {
    record(step) {
      undoStack.push(step);
      trim();
      redoStack = [];
    },
    undo: () => run('undo'),
    redo: () => run('redo'),
    dropDomain(domain) {
      undoStack = undoStack.filter((s) => s.domain !== domain);
      redoStack = redoStack.filter((s) => s.domain !== domain);
    },
    clear() {
      undoStack = [];
      redoStack = [];
    },
    registerFlush(flush) {
      flushes.add(flush);
      return () => { flushes.delete(flush); };
    },
    isBusy: () => busy,
    depth: () => ({ undo: undoStack.length, redo: redoStack.length }),
  };
}
```

// lib/undo/checkpoint.ts
// Whether a quiet moment is an undo step. Pure, for node --test.
//
// The checkpointed stores (markup objects, measurements, plane flags) are never mutated in
// place — every update goes through map/filter/spread — so element identity is exact. But a
// filter that removed nothing, or a delete of a text box created empty a moment earlier, still
// returns a NEW container. Comparing containers by identity would record those as steps that
// change nothing, so containers compare one level deep.

export function shallowEqual(a: unknown, b: unknown): boolean {
  if (Object.is(a, b)) return true;
  if (typeof a !== 'object' || typeof b !== 'object' || a === null || b === null) return false;
  if (Array.isArray(a) !== Array.isArray(b)) return false;
  const ra = a as Record<string, unknown>;
  const rb = b as Record<string, unknown>;
  const ka = Object.keys(ra);
  if (ka.length !== Object.keys(rb).length) return false;
  for (const k of ka) {
    if (!Object.prototype.hasOwnProperty.call(rb, k) || !Object.is(ra[k], rb[k])) return false;
  }
  return true;
}

/** The step a quiet moment records, or null when nothing really changed since the baseline. */
export function checkpointStep<T>(baseline: T, current: T): { before: T; after: T } | null {
  return shallowEqual(baseline, current) ? null : { before: baseline, after: current };
}
```

// lib/undo/shortcut.ts
// Which key events are undo/redo, and when the focused element owns them instead. Pure, for
// node --test.

export type UndoKey = 'undo' | 'redo' | null;

export interface KeyLike {
  key: string;
  metaKey: boolean;
  ctrlKey: boolean;
  shiftKey: boolean;
  altKey: boolean;
  isComposing?: boolean;
}

/**
 * Either modifier works on either platform, so a Windows keyboard on a Mac (or the reverse)
 * still undoes. Ctrl+Y is redo only as Ctrl: Cmd+Y is the browser's history in Safari.
 * `key` is lower-cased because Shift reports a capital Z.
 */
export function undoKeyOf(e: KeyLike): UndoKey {
  if (e.isComposing || e.altKey || !(e.metaKey || e.ctrlKey)) return null;
  const k = e.key.toLowerCase();
  if (k === 'z') return e.shiftKey ? 'redo' : 'undo';
  if (k === 'y' && e.ctrlKey && !e.metaKey && !e.shiftKey) return 'redo';
  return null;
}

/**
 * A focused text field keeps the browser's own text undo: the comment composer, a rename, the
 * calibration panel, and the markup text editor (a textarea).
 */
export function ownsTextUndo(el: { tagName?: string; isContentEditable?: boolean } | null | undefined): boolean {
  if (!el) return false;
  const tag = (el.tagName ?? '').toUpperCase();
  return tag === 'INPUT' || tag === 'TEXTAREA' || tag === 'SELECT' || !!el.isContentEditable;
}
```

'use client';

/**
 * Whether any pointer is held down anywhere in the window — mid-stroke, mid-drag, mid-gizmo,
 * mid-colour-picker. A checkpoint waits for this to be false, which is what folds one gesture's
 * many state writes (a group transform fires transformend once per node; a drag-erase deletes
 * one object per hit; a colour drag restyles every move) into one undo step.
 *
 * Capture-phase listeners on window, installed once on first use, so a handler that stops
 * propagation (Konva's cancelBubble, drei's pointer capture) cannot hide a press from it.
 * `blur` releases everything: a button released outside the browser window never sends
 * pointerup here, and a stuck "held" would block every checkpoint for the session.
 */
const down = new Set<number>();
const releaseListeners = new Set<() => void>();
let installed = false;

function release(pointerId?: number) {
  const wasHeld = down.size > 0;
  if (pointerId === undefined) down.clear();
  else down.delete(pointerId);
  if (wasHeld && down.size === 0) for (const cb of [...releaseListeners]) cb();
}

function install() {
  if (installed || typeof window === 'undefined') return;
  installed = true;
  window.addEventListener('pointerdown', (e) => { down.add(e.pointerId); }, true);
  window.addEventListener('pointerup', (e) => release(e.pointerId), true);
  window.addEventListener('pointercancel', (e) => release(e.pointerId), true);
  window.addEventListener('blur', () => release(), true);
}

export function isPointerHeld(): boolean {
  install();
  return down.size > 0;
}

/** Called each time the last held pointer is released. Returns the unsubscribe. */
export function onPointerRelease(cb: () => void): () => void {
  install();
  releaseListeners.add(cb);
  return () => { releaseListeners.delete(cb); };
}
```

export interface UndoShortcutOptions {
  /** Runs before an UNDO walks history. Return true to consume the press (e.g. abandon a half-placed measurement). */
  beforeUndo?: () => boolean;
  onFailed?: (outcome: { status: 'failed'; step: UndoStep; error: unknown }, direction: 'undo' | 'redo') => void;
}

/**
 * The one window listener for undo/redo. Separate from useUndoHistoryRoot because the page
 * needs the history BEFORE it creates the stores that record into it, and the options here
 * read those stores.
 */
export function useUndoShortcuts(history: UndoHistory, options: UndoShortcutOptions): void {
  // Read through a ref so the listener is bound once and still sees the latest callbacks.
  const opts = useRef(options);
  opts.current = options;

  useEffect(() => {
    const onKey = (e: KeyboardEvent) => {
      const which = undoKeyOf(e);
      if (!which || e.defaultPrevented) return;
      if (ownsTextUndo(document.activeElement as HTMLElement | null)) return;
      // A dialog or drawer owns the keyboard while it is open.
      if (document.querySelector('[aria-modal="true"]')) return;
      // Mid-gesture: the gesture is not a step yet, and undoing under it would tear it.
      if (isPointerHeld()) return;
      e.preventDefault();
      if (which === 'undo' && opts.current.beforeUndo?.()) return;
      void (which === 'undo' ? history.undo() : history.redo()).then((out) => {
        if (out.status === 'failed') opts.current.onFailed?.(out, which);
      });
    };
    window.addEventListener('keydown', onKey);
    return () => window.removeEventListener('keydown', onKey);
  }, [history]);
}

- [ ] **Step 3: Create the checkpointed state hook**

Create `components/undo/useCheckpointedState.ts`:

```ts
'use client';

import { useCallback, useEffect, useRef, useState, type Dispatch, type SetStateAction } from 'react';
import { checkpointStep } from '@/lib/undo/checkpoint';
import type { UndoDomain, UndoHistory } from '@/lib/undo/history';
import { isPointerHeld, onPointerRelease } from './pointerHeld';

export interface Checkpointed<T> {
  state: T;
  setState: Dispatch<SetStateAction<T>>;
  /**
   * Replace the state WITHOUT recording, and drop this domain's steps. For programmatic resets —
   * a file switch, the end of an annotation session, closing the cross-section tool — after
   * which the steps would replay onto state that no longer exists.
   */
  reset: (next: T) => void;
  /**
   * Hold checkpoints while `on` (e.g. a text editor is open, the calibrate tool is armed).
   * Releasing the last hold checkpoints on the next frame, so everything done while held is ONE
   * step.
   */
  hold: (key: string, on: boolean) => void;
}

/**
 * useState that records ONE undo step per quiet moment: no pointer held anywhere and no hold
 * active. A checkpoint is scheduled on every change and on every pointer release, and runs one
 * animation frame later, so every write from the same gesture — the per-node transformends of a
 * group transform arrive after pointerup — has landed first. The step is the net change from
 * the baseline (the state at the previous checkpoint) to now.
 */
export function useCheckpointedState<T>(
  initial: T | (() => T),
  history: UndoHistory | null,
  domain: UndoDomain
): Checkpointed<T> {
  const [state, setState] = useState<T>(initial);
  // Assigned during render, and ALSO written by undo/redo/reset directly: two undos in one tick
  // must not flush-compare against a state React has not rendered yet.
  const stateRef = useRef(state);
  stateRef.current = state;
  const baselineRef = useRef(state);
  const holds = useRef(new Set<string>());
  const frame = useRef<number | null>(null);

  const cancelFrame = useCallback(() => {
    if (frame.current !== null) {
      cancelAnimationFrame(frame.current);
      frame.current = null;
    }
  }, []);

  const checkpoint = useCallback(() => {
    cancelFrame();
    if (!history || holds.current.size > 0 || isPointerHeld()) return;
    const change = checkpointStep(baselineRef.current, stateRef.current);
    if (!change) return;
    baselineRef.current = change.after;
    const restore = (value: T) => {
      baselineRef.current = value;
      stateRef.current = value;
      setState(value);
    };
    history.record({ domain, undo: () => restore(change.before), redo: () => restore(change.after) });
  }, [history, domain, cancelFrame]);

  const schedule = useCallback(() => {
    cancelFrame();
    frame.current = requestAnimationFrame(() => {
      frame.current = null;
      checkpoint();
    });
  }, [checkpoint, cancelFrame]);

  useEffect(() => { schedule(); }, [state, schedule]);
  useEffect(() => onPointerRelease(schedule), [schedule]);
  useEffect(() => (history ? history.registerFlush(checkpoint) : undefined), [history, checkpoint]);
  useEffect(() => cancelFrame, [cancelFrame]);

  const reset = useCallback((next: T) => {
    cancelFrame();
    baselineRef.current = next;
    stateRef.current = next;
    setState(next);
    history?.dropDomain(domain);
  }, [history, domain, cancelFrame]);

  const hold = useCallback((key: string, on: boolean) => {
    const had = holds.current.has(key);
    if (on) holds.current.add(key);
    else holds.current.delete(key);
    if (had && !on) schedule();
  }, [schedule]);

  return { state, setState, reset, hold };
}
```

- [ ] **Step 2: Split the save out of the commit, and record a step after a successful save**

Replace the whole `handleTransformCommit` useCallback (from the comment `// Persist the 3D object's move/rotate gizmo transform once a drag ends.` through its closing `[selectedFileId]\n  );`) with:

```ts
  /**
   * Save the 3D object's placement. True on success. On failure, put the object back where it
   * is actually persisted: the gizmo has already moved the group directly, and nothing else
   * will undo that — leaving it there would mean the view and the stored placement disagree,
   * and any comment pin placed next would be saved against the wrong frame. A fresh object
   * identity is what makes the viewer's re-apply effect fire, since the values are unchanged.
   *
   * Shared by a drag's commit and by undo/redo, which re-save so everyone sees the model go back.
   */
  const saveObjectTransform = useCallback(async (fileId: string, transform: ObjectTransform): Promise<boolean> => {
    try {
      const res = await fetch(`/api/files/${fileId}/transform`, {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(transform),
      });
      if (!res.ok) throw new Error(`Transform save failed: ${res.status}`);
      // Keep the in-memory file in step so a re-render does not snap the object back
      // to the position it had when the list was last fetched.
      setFiles((prev) => prev.map((f) => (f.id === fileId ? { ...f, transform } : f)));
      return true;
    } catch (e) {
      console.error('Failed to save object transform:', e);
      setFiles((prev) =>
        prev.map((f) =>
          f.id === fileId
            ? {
                ...f,
                transform: {
                  position: [...f.transform.position] as [number, number, number],
                  rotation: [...f.transform.rotation] as [number, number, number],
                },
              }
            : f
        )
      );
      return false;
    }
  }, []);

  // Persist the 3D object's move/rotate gizmo transform once a drag ends, and make it an undo
  // step — only after the save succeeded, so a failed save never enters history.
  const handleTransformCommit = useCallback(
    async (transform: ObjectTransform) => {
      if (!selectedFileId) return;
      const fileId = selectedFileId;
      const before = filesRef.current.find((f) => f.id === fileId)?.transform;
      const saved = await saveObjectTransform(fileId, transform);
      // The person may have opened another file while the save was in flight; that file's
      // timeline must not receive this step.
      if (!saved || !before || fileId !== currentFileIdRef.current) return;
      // drei fires mouseup (and so this commit) for a click on a handle that moved nothing.
      // That re-save is harmless; an undo step that changes nothing is not.
      const same = (a: readonly number[], b: readonly number[]) => a.every((v, i) => v === b[i]);
      if (same(before.position, transform.position) && same(before.rotation, transform.rotation)) return;
      // A fresh copy per save, so the viewer's identity-keyed re-apply effect always fires.
      const put = (t: ObjectTransform) => async () => {
        const copy: ObjectTransform = {
          position: [...t.position] as [number, number, number],
          rotation: [...t.rotation] as [number, number, number],
        };
        if (!(await saveObjectTransform(fileId, copy))) throw new Error('Transform save failed');
      };
      undoHistory.record({ domain: 'model', undo: put(before), redo: put(transform) });
    },
    [selectedFileId, saveObjectTransform, undoHistory]
  );
```

`currentFileIdRef` already exists (declared ~line 479, above this callback) and always holds the selected file id.

          ? `Couldn't ${verb} — the model position wasn't saved.`
          : `Couldn't ${verb} that.`
      );
    },
